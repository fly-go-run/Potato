## 界面文案规则（2026-09-24）

修 bug 时容易给界面加一行“说明边界”的小字，这些小字是写给测试和审查的人看的，积累下来会让产品显得不成熟。新增或修改界面文案时遵守：

1. **默认不写小字。** 标题和按钮说不清楚，先改标题和按钮。
2. **只有不说会让用户吃亏时才解释**（不可撤销的删除、可能重复执行的操作、数据上传）。最多一句，优先放在确认弹窗里，不常驻页面。
3. **不承诺“不会丢”，不解释机制。** 不写“草稿会保留”“操作编号”“同步规则”“x / 20”；上限只在达到时提示。
4. **空状态只有一个图标、一句标题、一个按钮。** 没有内容时隐藏筛选、搜索和重复的添加入口。
5. **过程摘要只说做了什么，不写次数和秒数**（09-25）。"搜索网页""读取文件、执行命令""思考过程"；几次、几秒、几个来源留在点开后的详情里。停止、中断只在回复下方说一次。

厂商和基础设施名（Cloudflare、Exa、E2B、服务地址）只能出现在开发者选项中。

同一个信息只出现一次：图标已表明类型就不再写类型名，文件名带扩展名就不再写格式；两个入口通向同一内容时合并成一个。

图标规则（2026-09-24）：

1. **不用彩色底块。** 文件、功能图标保持单色墨色线条，不按类型配色；有真实内容时优先显示缩略图（文件首页、幻灯片渲染图）。
2. **一个动作一个图标。** 复制统一 `doc.on.doc`；同一屏里不能有形状相近但含义不同的图标。
3. **同一对象一个图标。** 电脑统一 `laptopcomputer`；系统符号自带灰色填充层时，用调色板渲染把第二层设为透明。
4. **面向普通用户的过程不用开发者符号。** 代码步骤按产物显示图标（演示文稿、图片），没有产物时用中性图标，不用终端提示符。
5. **回复下方的操作要安静**（09-25）。15pt 图标、比次要文字再浅一档，首个图标与正文左对齐，点击区仍为 44pt 高；本机与远程共用 `ReplyActionGlyph`。

## 产品与服务端约束

客户端是当前重点。用户接受先以 Cloudflare Workers 承载适合云端的业务接口，并暂不使用 VPS；这仍是架构方向，未部署服务。现有 potato-core 含桌面文件与进程能力，不能直接整体搬入 Worker。手机基础聊天与云端文件应能独立使用，电脑操作需另行设计桌面连接。
