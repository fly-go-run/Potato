# E2B + R2 跨对话检索：实施设计

日期：2026-09-13。用户选定继续使用 E2B，并同意沿外接持久存储方向设计。本文为设计基线，取代此前优先评估 Cloudflare Sandbox 的建议。iOS 首版已实现，实际协议、简化项、验证和上线状态见 [实施记录](implementation.md)；下文保留设计目标，不代表全部已落地。

## 第一版的用户体验

- 普通聊天保存在手机，同时把允许用于历史回忆的文字记录增量同步至个人云端空间。
- 新建聊天后，模型可以搜索过去对话，读取上下文，再回答「昨天问了什么」「最后选了哪件商品」，并提供原消息来源。
- 稳定偏好进入独立记忆条目；可查看、纠正和忘记。自动提取在回答完成后排队，不增加当前回复的等待。
- 首版覆盖 iOS 普通聊天正文与文字版本；附件内容、远程电脑任务、跨设备实时编辑不包含在首版。历史中的附件只记元信息，不默认上传其内容。
- 同步失败或只同步了部分历史时保留本地数据，并显示覆盖范围，回答不能把“没同步到”说成“你没提过”。

## 组件分工

| 组件 | 责任 |
| --- | --- |
| iOS | 本地保存、持久化同步队列、记忆管理、来源跳转、取消生成。 |
| Worker | 验证账号、接收同步、维护有效版本、模型工具调度、校验检索来源、写入记忆。 |
| R2 Standard | 对话对象、记忆条目与清单的持久副本，沙箱销毁后保留。 |
| E2B | 挂载或读取获授权的历史文件，执行搜索和上下文提取。 |

R2 是云端回忆的持久数据源，手机保留本地副本与未同步变更。不要在每次检索时上传全量历史，也不把临时沙箱磁盘当作唯一档案。

## 账号与存储布局

当前 `cloud.ts` 的 `cloudIdentity()` 已验证云端会话并返回账号标识，可作为云端路径映射的输入。旧个人模式的共享 `CLIENT_TOKEN` 不具有独立多用户身份：如支持此模式，必须由服务端明确绑定一个个人空间，不得从请求或模型提供的 user_id 选择目录，也不从令牌内容派生会随轮换变化的存储路径。

```text
users/<server-resolved-owner>/
  manifest.json
  conversations/<conversation-id>/<revision>.jsonl
  memory/<memory-id>/<revision>.json
  views/memory/<memory-id>.md
  views/MEMORY.md
  tombstones/<entity-id>.json
```

对话 JSONL 记录消息 ID、角色、发送时间、会话 ID、回复版本和原文。记忆 JSON 是结构化事实源，包含内容、状态、来源、有效日期与 revision；Markdown 是生成的可检索视图。记忆编辑通过服务接口修改事实源，不直接修改 Markdown 造成双重事实源。

清单记录当前有效 revision、时间范围、内容哈希与同步覆盖范围。先写不可变对象，再条件更新清单；对象成功而清单失败时重试，不把孤立对象暴露给检索。旧 revision 应按删除与保留规则清理，不承诺永久保留所有版本。

## 同步与检索协议

以下路径为接口草案，非已存在的 API。

| 接口/工具 | 行为 |
| --- | --- |
| `POST /v1/recall/sync` | 传操作 ID、实体 ID、base revision、内容与客户端时间；返回已接受 revision 或冲突。批量分块，符合现有请求大小限制。 |
| `GET /v1/recall/status` | 返回同步覆盖、待处理状态与有效版本，供客户端展示。 |
| `search_conversations` | 接收关键词/日期/时区，返回有上限的命中、消息 ID、片段、范围与分页。 |
| `read_conversation` | 按已验证的 ID、revision 与窗口读原文及相邻消息。 |
| `search_memory` / `read_memory` | 读取当前有效记忆和来源。 |
| `update_memory` / `forget_memory` | 写入结构化变更，校验来源、revision 与幂等键。 |

iOS 同步队列持久化，网络恢复或下次进入应用时重试。相同操作不重复写，base revision 冲突不静默覆盖；删除标记优先防止旧客户端重传复活内容。不要依赖 iOS 永久后台运行，也不要将完整同步任务仅放在 Worker 响应后的临时任务中。

当前服务端 `search-chat.ts` 已有 web_search 工具循环，历史检索应在同一服务端循环中扩展：Worker 调 E2B 后把受限结果返回模型。因为执行已移至云端，首版不需要之前本地方案中的“把通用工具请求下发手机执行”协议。iOS 仍需支持历史检索进度、来源事件和取消。

每轮生成绑定 generation ID、工具 call ID 和账号；设置轮数、运行时间与返回大小上限。自定义模型连接要显式确认工具能力，不支持时保留普通聊天。

检索先用日期/主题候选缩小范围，再查原文。中文两字词、型号、同义表达分别验收；grep 是一种执行手段，不能代替语义召回。是否引入 embedding 由同义召回结果决定。

## E2B 挂载与生命周期

现有 `sandbox.ts` 采用每次创建、120 秒 TTL、禁止互联网、结束后 kill 的方式，仅上传显式文件。新增专用 recall 执行入口和模板，复用现有 E2B 接入；当前通用文件分析入口保持自己的生命周期规则。

官方提供自定义模板安装 s3fs 后挂载 R2 的方法；这不依赖 E2B 原生 Volumes 的私有测试。挂载执行需要可访问 R2，不能原样保留 `allowInternetAccess: false`。[E2B 挂载指南](https://docs.e2b.dev/storage/cloud-buckets)、[网络配置](https://docs.e2b.dev/network/internet-access)

设计上只给 recall 沙箱当前用户数据的短期只读访问。R2 官方支持限定对象/前缀的临时凭证；父凭证保存在服务端，不进入沙箱。所选 s3fs 版本对 session token、目录列举和过期后的行为需要端到端验证，不能直接将长期密钥示例视为已完成的多用户方案。若挂载兼容性不通过，使用相同范围的临时访问把候选文件读入沙箱本地目录，保留 E2B + R2 架构。[R2 临时凭证](https://developers.cloudflare.com/r2/api/s3/temporary-credentials/)

首次以“一次回答内复用一个 recall 沙箱”控制成本，正常结束和取消时销毁；超时作为兜底。数据留在 R2，下次重新挂载。后续只有实测表明冷启动影响明显时，才引入短时保温。挂载数据的读取也有网络延迟，SQLite 和热数据处理放本地临时盘。

所有工具结果都要经 Worker 对照当前清单校验 ID、revision 和删除状态。原始对话内容作为历史证据传给模型，不作为新系统指令。沙箱不得任意修改历史档案或直接写入长期记忆。

## 记忆与删除

明确“记住/忘记”立即生成变更；自动记忆只提取有用户陈述依据的稳定信息。推荐、考虑购买、选定、已下单、取消分别表达；消息时间与事件时间分别保存，未知日期不补造。

自动记忆任务以来源 revision 为输入，写入前重验来源仍有效。用户纠正覆盖当前有效结论；忘记创建抑制记录，避免同一来源再次提取。关闭历史引用与删除内容是不同操作，界面明确区分。

删除先更新有效清单和 tombstone，立即排除检索，再清理对象、派生记忆、视图与缓存。运行中的检索在返回前再次校验。不能承诺撤回已经送给模型的文本；后续回答和再次查询必须遵守最新排除状态。

## 开发切分与验收

1. 用合成 JSONL 验证 E2B 读取 R2、范围隔离、临时凭证过期及沙箱销毁后重新访问。确认当前账号和套餐可用，不因设计自动开通服务。
2. 实现 iOS 分块同步、幂等处理、清单提交与删除传播；验证离线重试、未同步数据和 revision 冲突。
3. 扩展服务端历史工具循环及 iOS 来源跳转；验证新会话、昨天的自然日、商品改选/取消、中文检索与停止生成。
4. 加入记忆管理、自动提取、纠正与忘记；覆盖删除来源后重新提问、旧任务延迟写入和自动重复提取。

验收记录冷启动/已运行两种情况下的同步、挂载、检索、模型工具轮次、首字与总耗时，并统计每次回忆的运行时长和存储请求数。测试使用合成数据，直到真实数据同步功能和控制界面完成。

成本目标是继续使用现有 Worker 与 E2B，按需使用 R2；不新增 Cloudflare Sandbox 的固定套餐要求。R2 有独立开通与用量计费流程，不能将存在免费额度表述为无需开通或永远免费；当前账号实际额度和 E2B 费用尚未核验。
