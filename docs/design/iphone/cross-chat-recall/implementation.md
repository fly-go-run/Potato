# iOS 跨对话检索与记忆：首版实现记录

2026-09-13。用户明确要求实现 iOS，因此本次改动位于 `native/potato-ios` 与 `native/potato-worker`，不改旧 Web/Python 客户端。

## 已实现

- 在“更多 → 记忆与历史”开启跨对话检索；默认关闭，自动长期记忆为独立开关。手动添加、编辑和忘记记忆可直接操作。
- iOS 本地工作区保留原始消息。按稳定序列化内容哈希增量上传；仅完整消息和当前选定回复版本，包含消息时间、角色、消息/会话/版本 ID。示例、草稿、输入框、附件内容和远程任务不上传。
- 同步进度以本地工作区加每个服务/账号的已确认 revision 文件持久化。开启时、发送前、回答结束后、前台恢复及手动操作触发同步。第一次开启会同步本机现有的允许对话；失败显示错误，重新进入或发送时重试。同步冲突返回 409，保留两端数据，首版不提供自动冲突合并。
- 删除/排除先改本地状态并去掉缓存来源，云端 CAS 提交排除标记后不再检索，并清理旧对象及来源记忆。关闭总开关后仍能提交这些清理操作，不上传新增对话。离线时清理待下次联网同步。
- Worker 在现有流式工具循环中提供 `search_conversations`、`read_conversation`、`search_memory`、`remember`、`forget_memory`；不依赖 Exa 是否配置。
- 时间提示使用服务器当前时间及 iOS 时区；模型把“昨天”解析为自然日区间。检索按消息时间过滤，返回消息角色、原文、覆盖范围、分页、上下文。提示要求区分推荐、选择与已购买，不把无命中当作从未发生。
- 结果经过当前清单验证后，返回 `potato_recall` 进度与来源卡片；来源链接只接受实际检索返回的 ID。跳回本机原消息，不改变已有对话的回复分支。其他设备独有的原文不能直接打开，来源片段仍可读。
- 自动记忆由模型在回答内提出有用户原文依据的变更，成功回答结束前提交；取消、失败或无正文不提交。新增普通消息保持既有记忆有效，编辑/排除来源使其失效；忘记保留来源抑制标记，阻止同一来源自动重新提取。

## 实际存储与沙箱方式

```text
R2: potato-personal-recall
  recall/<SHA256(server-resolved-account)>/
    manifest.json                    # CAS 清单、记忆、排除和忘记标记
    conversations/<uuid>/<upload-uuid>.json

iOS protected local files:
  workspace.json
  recall-<SHA256(service + account-scope)>.json  # 已确认 revision
```

`cloudIdentity()` 决定账号；旧共享令牌模式始终属于固定个人空间，请求不能指定 owner。对话内容 SHA-256 为 revision，对象使用唯一上传 ID 防止并发恢复时清理错文件。先写对象再提交清单；版本冲突不暴露候选对象。正常提交清理旧对象；进程硬终止可能留下不被清单引用的孤立对象，后续运维清理应以当前清单为准。

首版采用**Worker 从 R2 读取候选对话，再经 E2B SDK 写入沙箱文件**，没有启用 s3fs/FUSE 挂载，不向沙箱发放 R2 凭据，也不需要开放沙箱外网。固定 Python 脚本读取 JSON，搜索中文关键词、型号和日期；查询文字不拼进命令。一个回答内复用一个沙箱，结束/取消释放，240 秒 TTL 兜底；脚本最多运行 30 秒。

这是设计允许的按需文件方式，避免引入尚未验证的临时令牌挂载兼容性。使用已有 `chat-web-office-pdf` E2B 模板和 `E2B_API_KEY` Secret。

## 与设计基线的差异和边界

- 记忆的结构化数据保存在清单中，未另外生成 Markdown 视图；历史按会话 JSON 文件组织。
- 自动提取属于当前模型的工具决策，没有额外后台模型任务或持久任务队列；保存失败在回答下提示。不会保证每次陈述都被自动记住。
- 首版是关键词检索，不含 embedding 或同义语义索引。每次工具最多读取 10 段候选/1.5 MB，每页返回 8 条、单条 4000 字符，可继续分页；每次回答最多 8 次工具调用。超过预算应说明覆盖有限。
- 单会话最多 512 KB/2000 条消息，最多 2000 段会话、200 条有效记忆，清单最多 1 MB。容量不足显式报错，不静默截断原始对话。
- 引用校验无法撤回已经送给模型的历史文本。删除后新的检索和记忆写入遵守当前清单；已生成的回答文字不会自动改写。
- 不支持跨设备原文下载、协同编辑或历史导入冲突解决 UI。已有回复版本保留在手机，云端只索引当前选中的完整版本。
