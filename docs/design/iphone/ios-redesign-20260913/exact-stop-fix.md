# 远程停止绑定到确认时的运行

2026-09-13，SwiftUI iPhone 客户端与 Rust potato-core 工作树修复，尚未发布。

## 问题与行为

原实现打开确认框后只发送 `chat_id`，电脑收到请求时再找当前运行。若第一轮已经结束、第二轮开始，确认第一轮的停止会取消第二轮；暂停后续队列和取消任务也分成两次锁定，存在同类竞态。

手机现在打开确认框时保存会话与运行编号。后台轮询即便读到新一轮，也不会替换这个确认目标。电脑在同一次 `outbox gate → runs → store` 锁定内核对编号、保存队列暂停状态并取消任务。编号过期返回 412，保留新运行及队列原状态。已成功请求仍按原操作编号返回持久回执，重试不会再次取消任务。

聊天快照声明 `stop_protocol: 1`。新版手机只有收到该声明和非空 `running_request_id` 才提供停止按钮，旧电脑显示更新提示。新版电脑对缺少编号的旧手机停止请求返回 422，避免继续接受无绑定请求。既有桌面原生停止入口仍可主动停止当前运行或暂停空闲队列，使用同一个原子处理路径。

## 验证

结果与截图存于 [QA 目录](../../../../native/potato-ios/qa/ios-audit-20260913/exact-stop-fix/)。核心 167 项通过、11 项既有可选测试忽略；新增测试进一步覆盖实际待发送队列保留、旧编号拒绝、正确取消、同编号回执重试与空闲桌面停止，两项定向测试再次通过。最终 Release 模拟器构建通过，产物不包含回环服务地址或远程过程预览开关。

iOS 单元测试 96 项通过。首次运行的 8 项 UI 测试因普通 shell 环境变量没有进入 XCTest runner 被跳过，不能作为页面验证；随后改用 `TEST_RUNNER_POTATO_IOS_PROCESS_UI=1` 重新执行。实际页面测试 iPhone 17 的 8 项、SE 的 3 项通过，均无跳过。截图核对发现旧电脑提示在一行内截断，已改为完整换行，并将提示测试改为最大辅助字号；最终同一条最大字号用例在 iPhone 17 和 SE 各通过一次，结果单列保存。两张最终截图均已人工查看，提示完整换行；正文仍可滚动，未用截图推断完整 VoiceOver 表现。

合成服务仅监听本机回环地址，所有任务、审批与指令都是测试数据。本轮没有调用真实模型、真实电脑或发布服务。线上中继和真实手机的端到端停止仍待联调。

## 当时的下一项：未完成发送回执

后续已实现 [回执恢复与未知记录处理](receipt-recovery.md)。以下保留本轮停止修复时的调查依据。

尚未修改回执恢复。本轮确认 `remote_command` 先在 SQLite 写入只有 fingerprint 的预留记录，执行后才保存 result/error；在两步之间退出会导致以后同编号永远返回 409。消息实际存于独立的追加式历史文件，不能将两处数据库锁误认为一次跨文件持久事务。

恢复必须以原操作编号对应的持久证据为依据：新发送和运行中补充都需要把操作编号与用户消息一起保存；补充消息从 queued 变为 delivered 时应保留这一关联。当前运行 ID 或终态 ID 可用于有限的旧记录恢复，但“创建了 remote-ID 会话”或“历史中出现相同文字”都不足以证明原指令已经接收。确认输入已保存也不等于任务已经执行完成，界面必须区分。

无法证明的旧预留记录需要可检查、保留原编号和原内容的显式处理入口，不能自动换编号重发或清空。此项与首页简化、完整 iOS 回归仍属于未完成工作。
