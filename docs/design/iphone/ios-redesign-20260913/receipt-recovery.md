# 发送回执恢复与未知指令记录

2026-09-13。修改 SwiftUI iPhone 客户端及 Rust potato-core，尚未发布。既有发送协议和中继操作白名单不变。

## 已接收输入的恢复

之前电脑先保存操作编号的预留记录，再执行发送，最后保存回执；中间退出后，同编号只能永远得到 409。消息历史与回执分别持久化在追加式文件和 SQLite，不能仅靠数据库锁把两者视为一个事务。

新发送和运行中补充指令现在将 `remote_operation_id` 与用户消息一起写入历史。补充从 queued 转为 delivered 时保留关联。手机沿用原编号重试，电脑核对原 fingerprint，再查原目标会话中精确关联的用户消息；找到后保存恢复回执并返回会话，不再次启动任务或追加输入。恢复读取完整历史，不受手机最近 120 条摘要截断影响。模型请求不携带这一内部字段。

手机恢复会话及草稿归属后，明确提示“指令已保存不代表执行已完成”，再读取真实任务状态。原输入与另一份编辑中的草稿沿用既有原子迁移规则，不把当前编辑内容当成重试负载。

只有相同文字、只有派生的新会话、会话被删除或历史无法核对时，保持未知结果。旧电脑、升级前没有关联字段的记录也不能凭猜测恢复，不会换编号自动重发。

## 未知结果的明确出口

待确认面板增加“核对并处理这条指令”。页面展示目标电脑、原会话或新任务、项目、内容、模型选择及原操作编号，说明它可能已执行，结束等待不会停止或再次发送电脑任务。用户确认理解后才可选择“保留记录并结束等待”。取消面板仍保留待确认状态。

该操作在同一个本机 JSON 文件更新中，将不可变请求存入按服务地址、账号及电脑隔离的未确认记录，解除 pending。输入框仍等于原指令时清空输入框，原文保留在记录中；独立编辑的草稿保留。之后的新会话、已有会话或应用重启都可从同一电脑的“未确认指令记录”查看原内容和编号，其他电脑不可见。这是保留未知记录，并非声称操作失败、完成或已取消；查看记录不发起网络重试。

旧草稿文件没有新增字段时正常读取。目标不匹配、待确认请求已改变或同编号内容冲突时不解除等待。本轮不自动删除未确认记录。

## 验证与实际限制

[QA 目录](../../../../native/potato-ios/qa/ios-audit-20260913/receipt-recovery/)保存源码摘要、测试结果、合成请求和实际页面截图。

- Core：169 项通过，11 项既有可选测试忽略。覆盖实际新建发送的 Chat Completions/Responses 请求、queued/delivered 补充恢复、重启后同编号重试、保留一条输入、不同 fingerprint 拒绝，以及同文、空会话、删除会话不触发执行。最后补充的两项回执测试再次通过。
- iOS：99 项单元测试通过。普通回执会话迁移、丢失响应后的不可变重试、恢复提示三条 iPhone 17 页面流程通过；未知记录核对流程修复后单独通过。第一次面板未取得请求内容，已改用 item 驱动呈现；第二次测试点中了开关的标签区域，依据截图把点击位置改为可见开关，两次失败均保留记录，不计为通过。
- Release 模拟器构建通过。恢复提示、确认前后按钮状态与重启后的原记录截图已人工核对。SE 的四条页面流程全部通过、无跳过，重启后的记录截图也已查看。请求日志中每条未知指令均只出现一次 send，保存记录和查看记录没有重发。

所有页面调用均走本机回环合成服务；核心模型协议测试只向合成 HTTP 服务发送请求，没有调用真实模型。当前没有真实电脑崩溃恢复或线上中继联调的证据，最低 iOS 17、完整 VoiceOver 与新面板的最大辅助字号仍待验收。

首页简化、远程长输入与附件、长中文快照预算、列表同步和完整 iOS 验收仍属于原目标的后续工作。
