# iPhone 工具过程与交付改版

2026-09-16。按用户提供的 9 张 Claude iPhone 截图重做，并按后续指示对齐其展示层级与样式。目标是现有 SwiftUI iPhone 客户端，未改 GPUI 桌面客户端。

## 参考中采用的结构

1. 聊天主线：思考摘要与状态始终单独可见，轻点直接打开完整思考记录；工具运行时显示当前动作，结束后收为「N 个步骤」，不展开工具日志。工具计数不包含思考。对应参考图 1、3。
2. 过程概览：原生半屏弹层、居中标题、圆形关闭入口、灰色图标与细线时间线。步骤是简短的动作标题，保留错误记录。对应参考图 4–7。
3. 工具详情：在同一弹层内进入下一层，返回保留聊天位置；输入和输出分别放在浅边框圆角区块中，代码显示语言标签并可选择、复制。对应参考图 8。
4. 图片结果：在输出区域保持完整宽高比，可打开 Quick Look 放大与分享。对应参考图 9。
5. 最终文件：单独的全宽交付卡片，突出文稿标题，次行显示类型、扩展名和大小，点击原生预览与分享。对应参考图 1。

## 实际实现

- `ActivityPresentation.swift` 统一本机与远程的过程视图，替换原有行内思考展开和代码 DisclosureGroup；正文中的来源入口保留。
- 本机将思考、搜索、历史检索和代码执行汇入过程概览。新记录保存工具首次出现的顺序；推理文字仍是上游提供的公开思考记录，按原协议累计，不生成额外的“思考”。
- `activityOrder`、调用的 `attachmentIDs` 以及可选动作 `title` 跟随消息、回复版本与重启持久化。同名图片按附件 ID 关联到实际生成调用。
- 远程调用与输出按 call ID 在同一过程组内配对，孤立输出保留。非零 shell 退出码显示失败，失去状态确认时不显示运行动画或推测成功。
- 代码输出超过 4,000 字先显示预览，可展开完整内容；复制始终复制完整内容。
- 图片解码在后台进行并限制预览像素大小；输入、输出和步骤列表支持 Dynamic Type。
- PPTX 通道补齐 iPhone 本地保存、文件类型识别与 Worker MIME 输出白名单。
- Worker 的 `run_python` 接受可选 `description`（最长 120 字），向 iPhone 的运行、完成和失败事件传递动作标题；未提供时仍兼容旧协议。
- PPTX 回复的关联渲染图片收进对应步骤，主聊天先展示交付卡片再展示说明，避免中间预览占满正文。无 PPTX 或无调用关联的图片仍保留在主聊天。

## 验证边界

iPhone 客户端已发布至 TestFlight 0.2.2（2026091603），既有个人内测组 Testing。见 [发布记录](release-2026091603/README.md)。本轮 Worker 尚未部署，新增动作标题和 PPTX MIME 扩展仍需配套服务发布。

本机与远程的结构不同：本机有真实沙盒文件/图片结果；当前远程消息协议只有文字、参数和输出，没有可供手机获取的图片/文件资源。因此远程覆盖步骤与文本详情，不声称已经支持远程图片传输。

旧记录没有工具穿插顺序或附件来源 ID，仍能读取其日志与聊天附件，但不会凭文件名猜测归属。旧累计推理内容也不会被伪造为多个精确的中间思考事件。

UI PPTX 样例由 python-pptx 在本地生成，预览由 LibreOffice 和 pdftoppm 渲染。`--ui-testing --reset --activity-preview` 仅在 DEBUG 中启用，验证完整的展示和文件预览，不调用线上模型，不代表已执行线上 PPT 制作任务。

具体截图、视觉对照与验证结果见 [design-qa.md](design-qa.md)。

## 发布前思考入口修正

根据用户反馈，思考不再仅藏在步骤入口里。本机与远程共用的主线入口显示已有思考内容的摘录与状态，点击直接查看完整记录。工具步骤单独收起；概览仍保留已有的思考与调用顺序。未提供思考内容的模型不会被伪造补齐。
