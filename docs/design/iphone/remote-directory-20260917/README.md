# 远程列表优先显示缓存

2026-09-17，原生 iPhone 客户端工作树修改，尚未发布 TestFlight。

后续按用户反馈移除了常规连接／更新小字及预留空行；本文记录初版验证，最新行为和截图见 [精简加载提示](../quiet-loading-20260917/README.md)。

## 用户提供的过渡与参考

1. 原先先显示添加电脑引导：已关联账号尚未返回电脑列表时，界面把“还没读到”当成了“没有”。
2. 接着显示离线提示：`online[id]` 缺失与明确的 `false` 混在一起，未确认连接被误显示为离线。
3. 最后显示项目／会话：这才是返回用户的主要界面。以用户选定的第三张为布局基础，并参考后续 Claude、GPT 截图中“会话列表持续存在，设备状态独立更新”的行为。

## 当前行为

- 成功读取后，保存设备、项目、会话标题／标识／置顶信息。重开 App 同步恢复列表，随后后台连接。
- 缓存不保存在线状态。初始为灰色未连接状态，收到在线确认后变绿；VoiceOver 同时获得未连接／正在连接／在线／离线／连接未确认的文本状态。
- 已缓存的列表不被加载页或离线页替换。状态文字占用固定高度，连接前后同一会话行的纵向位置测试保持一致；已有在线状态的定时刷新不反复显示进度提示。
- 使用不自动降低文字透明度的列表按钮样式；未连接和在线时标题均保持正常对比度，连接状态由设备指示灯和小字表达。
- 首次没有缓存时显示项目和会话的加载占位。成功确认没有设备后，才显示精简的添加电脑说明；请求失败保留缓存或显示重试入口，不冒充空账号或电脑离线。
- 电脑离线／手机网络失败均保留列表。连接未确认时，打开远程会话和发送入口仍不可用；不把缓存当成执行权限。
- 缓存按当前账号、服务地址和目标电脑核验；退出、移除、撤销及服务器确认移除设备后清理相应缓存。刷新跨后台或目标移除后的迟到响应不能恢复旧目标。

范围是远程首页的列表缓存，不包含远程会话消息全文离线阅读。本次未改 Worker、桌面 GPUI 或 potato-core。

## 验证

- 全量 177 项 iOS 单元测试通过，其中新增 8 项目录缓存／连接状态测试。
- 4 条新增界面测试通过：首次慢加载、重启先显示缓存且回连不跳位、离线及网络错误保留列表、确认无设备后才出现添加入口。
- 既有远程导航／搜索／侧栏、远程首页语音入口各 1 条回归通过。
- 测试为 iOS 26.3 模拟器、隔离的 UserDefaults 和合成远程列表，不访问真实电脑或线上账号；真机启动耗时尚未测量。
