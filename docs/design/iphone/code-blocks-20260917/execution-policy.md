# 示例代码的执行与展示规则

2026-09-17，用户反馈已发布的 2026091702 中，仅要求“写一段 Python 代码”就触发一次沙箱执行，且回复正文将 text 输出放在 Python 源码之前。

## 原因核对

- iOS MarkdownContent 按 MarkdownBlock.parse 的原始顺序显示；正文里的 text/python 块没有按语言重新排序。工具过程入口单独位于正文上方，但截图中的 text 输出位于正文内部。
- Worker 的模型请求使用 tool_choice: auto，是否调用由模型决定，不是客户端检测到 Python 代码块就自动执行。
- 旧系统提示允许“when useful”执行，并写有“Run the code yourself rather than asking the user to click a code block.”；工具描述另有“Decide when execution helps.”。这些表述允许模型为普通示例主动运行，未限定代码编写/解释请求。没有强制每段代码都运行，但确实有主动执行倾向。
- 上一版 iOS 移除的是手动按钮与弹窗，没有修改 Worker 的提示规则。

## 已部署的修改

在 code-tool.ts 定义同一份 pythonExecutionPolicy，供工具描述和 search-chat.ts 系统提示复用：

1. 写、解释、修改或演示代码不等于要求执行；默认只给代码，不为验证普通示例而运行玩具数据。
2. 用户明确要求执行/测试，或目标需要实际计算、处理输入数据/文件、制作可下载文件/图表时，仍可直接调用沙箱。
3. 遵守“不执行”的指示；不提示点击代码块。
4. 同时展示代码和对应输出时，源码在前、输出在后，除非用户指定其他顺序。
5. 普通示例默认不加输出；确需解释的未执行输出明确标为预期/示意，不冒充真实运行。

不在客户端擅自重排模型正文，不采用关键词拦截来替代模型理解，也不关闭处理文件等任务所需的沙箱能力。
