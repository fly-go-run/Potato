# iPhone 快捷附件面板

参考用户提供的 DeepSeek 与 Claude 截图，采用精简的底部面板。覆盖 `native/potato-ios` 本机聊天的「＋」入口。

## 交互

- 拍照与最近 30 张可访问照片位于同一横向列表，最新照片靠前；所有照片打开系统选择器。
- 轻点最近照片立即导入当前消息，不需要“完成”确认；面板保持打开，可连续添加。
- 缩略图显示处理中、已添加或重试状态；再点已添加照片即可移除。
- 按用户反馈移除“轻点照片即可添加，关闭后可继续编辑。”底部说明，仅保留数量及满额提示。照片与文件共用 20 个名额。
- 关闭面板后继续编辑文字、预览或移除附件；点击发送才调用模型。选择照片不会自动发送消息。
- 保留选择文件、从资料库选择；每条消息最多 20 个附件，正在导入的附件也占用名额。
- 导入队列属于聊天页面，关闭面板不取消导入。按点击顺序处理，绑定原会话，失败单项释放名额，其他附件继续处理。

## 权限与数据

最近照片仅在用户点击“允许访问照片”后申请 PhotoKit 读取权限。有限授权只展示获准照片，提供管理入口；拒绝授权仍可使用系统“所有照片”选择器。相机权限只在点击拍照时申请。中英文用途说明已加入。

缩略图不下载完整 iCloud 原件。只有点击的照片进入导入队列；最近照片原件下载超时 60 秒后显示重试状态。沿用现有沙盒保存与 JPEG 压缩限制，服务端仅放宽聊天图片数量校验。

参考：[Apple PhotoKit 授权与有限照片库 API](https://developer.apple.com/documentation/photos/phphotolibrary)。

## 实现

- `AttachmentSheet.swift`：原生附件面板、相机和文件选择器。
- `RecentPhotos.swift`：照片库权限、变更观察、缩略图与原件读取。
- `ComposerAttachments.swift`：导入预留名额、去重、顺序、失败恢复与会话归属。
- `WorkspaceView.swift`：替换旧菜单，复用草稿附件预览与发送链路。

初版（4 张上限）使用独立 iPhone 17 / iOS 26.3 模拟器，以真实 PhotoKit 照片库和本地参考图片验证。原生模拟器构建通过，21 项单元测试和 8 条 UI 场景分批通过；20 张调整验证见下节。摘要见 [validation.txt](validation.txt)。

- 单元测试：ComposerAttachmentTests 5 项、LanguageTests 5 项、WorkspaceTests 11 项。
- UI：最近照片立即添加、连续选择与上限、关闭和重启保留、深色、大字号、照片拒绝授权回退、照片/文件/相机返回及资料库跳转、系统照片导入预览与移除。
- 相机测试最初误假设模拟器不提供相机，随后依据录屏调整为验证真实相机界面的关闭返回；最终该场景通过。没有将早期测试失败当作客户端文件选择器缺陷。
- 已检查浅色、已添加、草稿、数量上限、大字号、深色及拒绝授权截图。

测试前在专用模拟器照片库导入至少 20 张图片，并允许测试应用访问照片；权限用例会主动重置授权。

## 20 张附件调整

客户端导入、资料库复用、输入框计数共用 `Attachment.maximumPerMessage = 20`。云端 Worker 的聊天校验同步支持 20 张图加文字，21 张图会被拒绝。请求仍受 4 MiB 限制，沿用发送前按全对话图片数量分配压缩预算。

22 项 iOS 单元测试通过，覆盖连续预留 20 个名额、第 21 个拒绝、资料库原子性以及 20 张高熵图片全部序列化且压缩后请求不超限；22 项 Worker 接口测试和 TypeScript 检查通过。4 项 UI 场景分批通过：轻点添加及草稿保留、连续添加 20 张并删除恢复名额、深色关闭及重启保留、大字号。浅色、草稿、上限、深色及大字号截图已更新；拒绝授权截图保留初版状态。

发布顺序：先部署 Worker，再发布 iOS。2026-09-19 已完成云端部署与 TestFlight 0.2.2（2026091901）个人内测分发，确认 Testing。代码执行工具的输入文件限制与聊天图片限制独立，本次保持原有数量和总大小预算。
