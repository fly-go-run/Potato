# iPhone 资料库设计定稿

日期：2026-09-16。状态：已按用户选定的第三版「文档列表 + 图片网格分区」实现 iPhone 原生资料库；验证与限制见 [实现记录](implementation.md)。

视觉稿使用内置 ImageGen 生成，按本轮对话实际展示顺序保存：[1](01-grid.png)、[2](02-list.png)、[3](03-grouped.png)。它们是概念图，示例文件和缩略图不是用户真实资料。

实现以 [第三版视觉稿](03-grouped.png) 为依据；第一、二版仅保留为探索记录。用户随后明确要求开始完成实现。

## 目标与依据

资料库管理可保存、查找、预览并用于对话的文件：图片、文档、保存的文本，以及对话生成的文件。用户提供的 ChatGPT iPhone Library 截图是结构参考；Potato 现有米白背景、深灰文字和系统玻璃控件是视觉依据。

本次针对 iPhone 资料库设计与实现，不修改 GPUI 或旧桌面实现。下文的问题描述记录改版前的源码现状；实现验收独立列在实现记录。

源码确认的问题：`WorkspaceSidebar` 的「资料库」打开 `.history`，由 `LibraryView` 展示 `Conversation`，搜索标题及消息，页面标题为「对话」。因此入口语义与内容不符。现有 `Attachment` 附属于对话，清理逻辑只检查对话及版本中的文件引用，尚无独立资料收藏记录。

## 页面与信息层级

- 顶部：侧栏按钮、居中的「资料库」、更多菜单。资料库作为主内容页面展示，保留来源对话和输入草稿以便返回。
- 分类：全部 / 图片 / 文档；文档包含 PDF、文本、Markdown、表格与演示文稿等可保存文件，不将聊天消息当作文档。
- 默认排序：最近添加。更多菜单提供排序、选择资料、资料最近删除；首期按类型固定呈现，不再加入网格/列表切换。
- 文件标题：最多两行，保留类型信息；完整名称在预览页显示。无标题粘贴文本采用首个有效标题或首行，避免大段时间戳占满卡片。
- 缩略图：图片等比裁切，预览时显示原图；PDF 用第一页，文本用可读的内容片段，不支持的预览使用类型图标。
- 底部：玻璃搜索栏「搜索资料」及独立「＋」。滚动内容有足够底部留白，最后一项可完整滚出工具栏。
- 大字号自动回退单列；点击区域至少 44pt，VoiceOver 读出文件名、类型与选中状态；减少透明度模式提供实色背景。

选定方案采用文档列表与图片网格分区。生成图仅为视觉概念，具体字号、图标与玻璃效果在原生实现时校准。

### 第三版的页面规则

| 页面 | 内容与操作 |
| --- | --- |
| 全部 | 上方「文档」显示最近 3 项，下方「图片」显示最近 4 项；只有超出预览数量时显示对应「查看全部」 |
| 文档 | 连续纵向列表，左侧缩略图，右侧文件名、类型、大小和添加日期；每行更多菜单提供重命名、分享、删除 |
| 图片 | 双列缩略图网格，图下显示文件名及大小、日期；长按或预览页更多菜单提供文件操作 |
| 搜索结果 | 在当前分类内展示全部匹配项，不受首页 3/4 项限制；「全部」搜索按文档、图片分组显示完整结果 |

「查看全部」直接切到对应分类，不再叠加一层重复页面；返回「全部」恢复原浏览位置。分类均为空时显示全页引导；只有一个分类为空时隐藏该空分区，独立分类页提供针对性的添加入口。文档和图片各自按所选规则排序，默认均为最近添加。

普通字号下页面左右留白约 20pt，文档缩略图 80 × 64pt，图片间距 12pt、圆角约 12pt；文档行保持轻量，不增加大块卡片背景。文档主标题 16–17pt，元信息 13pt，分区标题约 20pt，控件触控范围至少 44pt。首页文档区限定 3 项，避免文件增多后图片区被持续挤到很远的位置。底部搜索与添加保持第三版的位置关系。

### 预览页结构

顶部返回按钮和更多菜单，中间为文件内容，底部固定「用于对话」主按钮。完整文件名和类型信息放在内容上方；长名称可换行，来源对话放在「文件信息」中以免挤占预览。图片预览保留原始比例并可缩放，PDF 首次打开第一页，文本可滚动阅读；分享、重命名、删除集中在更多菜单。

从首页、分类页或搜索结果进入预览再返回，均保留分类、关键词和滚动位置。添加成功后进入新资料预览；返回时切到该文件所属分类并定位新文件，避免当前筛选使用户误以为保存失败。

## 关键交互

### 添加

「＋」打开系统样式菜单：从照片选择、从文件导入、粘贴文本。粘贴必须由用户主动触发；先允许检查和命名，再保存。导入后显示进度、成功结果或可操作的错误，失败保留重试入口，不产生虚假的成功卡片。

正式发送成功的用户附件和已下载成功的生成文件默认加入资料库；未发送的临时附件仍属于草稿。普通文字回复仅在用户选择「保存到资料库」后成为文本资料。远程文件只有可获取实际文件时才纳入，不能把远程路径当成本地文件。重复保存按文件内容与来源去重，保留来源关联。

### 预览与复用

点击资料先预览。预览页显示完整文件名、类型、大小以及可用的来源对话入口。图片支持缩放；PDF 支持翻页；其他文件使用系统预览能力，失败时仍可导出。

主要操作「用于对话」：若从一段对话进入资料库，将所选文件加入该对话输入框并返回；也可选择「新对话」。操作不自动发送。多选模式底部提供「用于对话」「分享」「删除」，并显示选中数量。模型不支持某种附件时解释限制，允许更换模型或取消选择。

### 搜索

先覆盖文件名；有已提取文字的资料支持正文检索。搜索与当前分类共同生效，显示匹配片段；图片的 OCR、图像语义搜索和云盘全文搜索不作为首期承诺。输入时搜索栏随键盘抬升并提供取消，取消恢复原筛选和滚动位置。

### 删除和留存

资料与来源对话独立留存。删除对话不删除已入库资料；从资料库删除也不破坏历史消息中的附件。资料先进入独立的「最近删除」，可恢复或明确永久删除。永久删除资料库条目后，仍被聊天引用的文件保留，界面需说明这一行为。文件的物理清理须同时检查资料、草稿、消息和回复版本引用。

原对话历史管理仍属于侧栏；现有对话「最近删除」需保留独立入口，不能因替换资料库页面而丢失恢复能力。

## 必需状态

| 状态 | 页面行为 |
| --- | --- |
| 无资料 | 「把文档和图片放在这里，随时用于对话。」与「添加资料」按钮 |
| 分类为空 | 「还没有图片」或「还没有文档」，保留其他分类切换 |
| 搜索为空 | 「没有找到相关资料」，可清除关键词和筛选 |
| 导入中 | 文件占位项显示进度，可取消，不阻塞继续浏览 |
| 无法预览 | 保留文件名与格式，提供系统打开/分享和重试 |
| 只能保存，不能用于模型 | 明确显示「此格式暂不支持用于对话」，仍允许管理与导出 |
| 文件不可用 | 明确提示重新导入，不使用空白缩略图冒充正常文件 |

## 实现边界，供后续开发

当前普通导入仅支持图片、PDF 和文本，存在 10 MB 与提取文字长度限制，并会把图片转成 JPEG；生成产物另有 Office 格式保存路径。设计中必须区分「可保存」「可预览」「可用于模型」，不能把格式图标当作解析能力已经具备。资料库应保存原文件，缩略图和模型输入转换独立生成；扫描 PDF 即使无法提取文字，也应能保存与预览。

后续需要新增独立资料记录及持久化版本迁移，字段至少包含资料 ID、文件引用、显示名、MIME、大小、添加时间、来源关联、删除状态；缩略图与文本提取为可重建的派生数据。历史现存附件按实际文件迁入，过滤失效引用并去重；缺失文件明确提示，不触发清理或重写用户历史。所有引用检查都更新后，才能恢复未引用文件的物理清理。

首期以本机资料库落地，清楚标注存储范围。云盘连接、跨设备同步、文件夹、自动标签和语义搜索另行设计。参考截图中的 Google Drive 卡片不代表当前已经支持该连接。

## 验收重点

进入资料库看到文件，侧栏仍能浏览和恢复历史对话；图片与文档可筛选；导入文件后重启仍存在；预览、重命名、搜索、复用、分享、删除与恢复形成完整闭环；删除来源对话不丢资料，删除资料不破坏历史附件；底部最后一项可完整操作；键盘、大字号、减少透明度和空状态可用。此处为未来验收清单，并非已通过的测试结果。
