# Potato 体验审查与本轮重构

## 审查范围和方法

通过 Computer Use 检查 `/Applications/Potato.app` 的实际设置页、首页和历史对话，再在 `http://127.0.0.1:5174` 使用当前源码连接同一本机后端进行改版回看。后端版本接口返回 2.0.6。

检查设置各分区、服务商详情、浅色/深色、工具长列表、设置快捷键、Escape 返回、历史会话、模型菜单。没有发送测试消息、改动模型连接或变更安全权限。预览中的主题在检查后恢复为跟随系统。

这是交互观察与源码审查，不是 FPS、启动耗时或长会话性能基准。浏览器验证不能证明新代码在原生窗口中的拖动、缩放、语音和系统权限路径已通过。

## 第二轮修复（含用户追加反馈）

- 工具过程运行时显示动作名称与最多三行实际输出，完成后默认仅保留可展开的动作行；命令、参数和完整结果按需展开。单次工具不再套一层总步骤标题，多次调用聚合折叠。失败及隐藏错误输出的调用保持可见。
- 思考标题默认隐藏；对用户的进展描述保留为正文，工具计数只统计真实工具调用。保留手动展开状态；流式日志使用有界预览。
- 历史 `find ... -printf ... 2>/dev/null | sort` 在 macOS 存在命令兼容性问题。现在明确显示无输出与隐藏错误提示；未更改历史答案。Python Shell 为 bash/zsh/ksh 开启 pipefail，避免最后一个管道命令成功掩盖前面的失败；无 stdout 文案不再作为数据为空的证据。Windows/显式 sh 的行为未因此改写。
- 模型选择改成可搜索的服务商分组面板，当前模型置前；同名项显示完整 ID，支持方向键、Escape 和可见的错误重试。思考深度保留在面板底部。
- 连接草稿在返回、关闭、分区切换、Escape、⌘, 时受保护；浏览器历史导航离开后保留内存草稿，下次进入恢复，不将 API key 草稿写入磁盘。页面刷新使用浏览器 beforeunload 提示。
- 安全设置区分“系统隔离”“默认执行范围”“操作确认”，保留真实的不可用原因，不更改用户权限策略。
- 默认改为中性黑白，移除青绿色选中态及偏蓝背景。macOS 使用系统字体/苹方，恢复系统字体平滑，提高正文、导航、工具文字字号与对比度；浅深色与自定义主题入口保留。

- 前端 37 个测试文件、322 项通过；Shell 和后台 Shell 测试 81 项通过。TypeScript 与生产构建通过。
- Computer Use 验证：单工具短结果、多工具展开后直接显示逐项短结果、模型筛选与方向键、设置草稿取消后保留、⌘, 关闭保护、丢弃后返回、浅深色与跟随系统。未保存测试连接、未切换真实模型、未发送测试消息。
- 已查看同目录任务“评估 Rust 重写后端”：它负责 Tauri/Rust 核心、接口和启动迁移。本轮不修改 Cargo、Rust、API 传输、桌面桥接或启动配置，也不打包替换正在使用的客户端。
- Python Shell 修改位于 `src/potato/agents/tools/shell.py`，配套回归在 `tests/unit/agents/tools/test_shell.py`。迁移到 Rust 时需保留管道退出码和无输出不等于数据为空的语义。
- 改动已进入源码与本地前端预览。安装版未替换，原生窗口、Windows 字体及 Rust 后端联调待迁移构建后验证。
- 入口约 392 kB 的构建提示仍在。长会话/流式滚动和启动耗时尚未做性能基准；不以静态截图宣称性能问题已经全部解决。

## 参考图追加校正：进展描述与工具详情

用户提供 Codex 截图后发现，上一轮把面向用户的过程旁白一起隐藏过度。现在保留“先检查什么、发现什么、接着做什么”的原始消息位置，完成后只收起普通工具输出。带中间描述的过程不再使用一轮总折叠把工具与对应描述拆开；无中间描述的多工具序列继续聚合。思考通道标题仍默认隐藏，错误和不确定结果例外保留。复制按钮依然只复制最终回答。

Computer Use 在“执行系统命令三步操作”历史会话验证了描述保留、完成态输出隐藏、手动展开 date 返回原始结果；没有实际发送新请求，实时结束瞬间的视觉过渡仍需流式回放验证。前端 322 项测试、生产构建通过。

### Shell 结果面板

按用户参考图增加浅灰圆角面板、Shell 标题、命令区、独立滚动的等宽输出、复制命令与输出、底部执行状态。输出保持原始列对齐，长行横向滚动。活跃 Shell 默认展示面板，自动展开在完成时收起，用户手动展开的选择保留；流式日志跟随底部，手动上翻后停止跟随。错误与隐藏 stderr 的结果不标成成功。

Computer Use 验证了 df -h 长输出的展开外观、输出区和底部完成状态，点击复制出现“已复制”。前端 322 项测试与构建通过；实时流式滚动和自动收口代码已实现，尚未用真实新请求回放验证。

## 结构化提问与选项回答

新增输入框上方的提问卡片，支持单选、多选和自由文字，默认不选中任何答案；用户可以补充文字、跳过或收起卡片。提交失败保留草稿，切换会话再返回可恢复本次页面内的草稿；提交按钮防止重复触发，已提交的问题不会被较早的轮询结果重新显示。历史消息使用问题标题作为引用，正文呈现选项标签和补充文字。

前端通过 GET /api/questions?session_id=... 获取待答问题，通过 POST /api/questions/{id}/answer 提交 selected/text/skip。与“评估 Rust 重写后端”任务协作，由其实现 request_user_input 工具和问题持久化：等待用户时保持任务活动，回答后恢复模型执行。旧 Python 后端不支持该接口时不显示卡片；功能需要 Rust 预览版，未替换安装版。

Computer Use 在本地模拟页面 /qa/question.html 验证：未填写禁用提交、多选与文字组合、单选互斥、纯文字回答、跳过清空答案、失败保留输入后重试成功。页面明确标注模拟问题，不调用模型或改动真实会话。Rust 任务报告 15 项测试通过，包含模型提问→待答→回答入历史→模型继续的完整回路，以及幂等、409 冲突和取消持久化。真实外部模型服务与安装版尚未实测。
