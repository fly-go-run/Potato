# Native Office tools

Office generation and template filling run inside the Rust core. There is no
Python, Node, LibreOffice or Docker runtime dependency. These tools provide
bounded document operations; they are not a complete Office editor or renderer.

## Open-source engines and reference designs

| Component | Version / license | Role |
| --- | --- | --- |
| [ppt-rs](https://github.com/yingkitw/ppt-rs) | 0.2.25 / Apache-2.0 | PPTX slide packages and placement |
| [docx-rs](https://github.com/bokuweb/docx-rs) | 0.4.22 / MIT | DOCX title and paragraph generation |
| [rust_xlsxwriter](https://github.com/jmcnamara/rust_xlsxwriter) | 0.99.0 / MIT OR Apache-2.0 | XLSX files and consistent chart XML/data |
| [IronCalc base](https://github.com/ironcalc/IronCalc) | 0.8.3 / MIT OR Apache-2.0 | Actual numeric formula evaluation |

The implementation uses the following design ideas from other languages, not
copied source code or a new runtime:

- [XlsxWriter formula results](https://xlsxwriter.readthedocs.io/working_with_formulas.html):
  distinguish a formula from its cached value. Unlike XlsxWriter's default zero
  cache, Potato evaluates supported formulas using IronCalc before writing them.
- [PptxGenJS charts](https://gitbrent.github.io/PptxGenJS/docs/api-charts/):
  explicit categories/series and deterministic chart rectangles.
- [pptx-automizer](https://github.com/singerla/pptx-automizer): modify existing
  template content while retaining the package's other resources.
- [python-pptx text hierarchy](https://python-pptx.readthedocs.io/en/latest/user/text.html)
  and [python-docx-template](https://github.com/elapouya/python-docx-template):
  treat paragraphs and formatted runs separately when filling placeholders.
  No LGPL template implementation or proprietary legacy skill code is copied.

Keep upstream license notices when distributing dependencies. `ppt-rs` 0.2.25
requires its `pdf-native` feature to compile because of an unconditional `pdfrs`
import. PDF export remains unexposed: its standard-font renderer is not evidence
of Chinese font or full Office rendering fidelity. Native compression libraries
are transitive build dependencies; no language interpreter is required at runtime.

## Create editable files

Use `create_office_file`. Existing output files are never overwritten. Parent
folders must exist. Paths are confined to the conversation project and normal
write/approval policies apply.

### PPTX

```json
{"file_path":"plan.pptx","format":"pptx","document":{"title":"研发计划","slides":[{"title":"阶段安排","bullets":["接入开源引擎","验证中文内容"],"notes":"讲者备注"},{"title":"季度数据","bullets":[],"chart":{"kind":"column","title":"实际与计划","categories":["第一季度","第二季度"],"series":[{"name":"实际","values":[12,24]},{"name":"计划","values":[15,30]}]}}]}}
```

Chart kinds: `column`, `bar`, `line`, `pie`. Up to 30 categories and six series;
pie requires one series. Series lengths must match categories. Chart slides
require empty bullets, preserving a title region above a fixed 9 x 5.4 inch chart
rectangle on a 10 x 7.5 inch slide. This avoids body/chart overlap by construction.

**Upstream chart correction:** ppt-rs currently embeds a fixed reference workbook
and some chart XML references use a fixed column. Potato replaces both the chart
XML and embedded workbook with a matched pair generated by rust_xlsxwriter.
Displayed series caches and PowerPoint's editable source data therefore use the
same input values, including multiple series.

### DOCX

```json
{"file_path":"report.docx","format":"docx","document":{"title":"研发报告","paragraphs":["完成原生文件生成。","下一步验证视觉效果。"]}}
```

### XLSX with calculated formulas and formatting

```json
{"file_path":"budget.xlsx","format":"xlsx","document":{"sheets":[{"name":"预算","header":true,"column_widths":[24,18],"number_format":"0.00","rows":[["项目","金额"],["研发",12000],["测试",3000],["合计",{"formula":"=SUM(B2:B3)"}],["平均",{"formula":"=B4/2"}]]}]}}
```

Strings remain literal, even `"=1+1"`. Formula objects are explicit. Supported:
uppercase `SUM`, `AVERAGE`, `MIN`, `MAX`, `COUNT`, `ABS`, `ROUND`, numeric arithmetic,
percentages, parentheses, and same-sheet A1 references/ranges (including `$`).
References must remain within the supplied sheet rectangle. Formula results must
be finite numbers; parse errors, division by zero, cycles and unsupported results
reject the entire output. IronCalc computes dependencies and the XLSX contains
both formula expressions and their real cached results.

This evaluates new workbook inputs. It does not import/recalculate arbitrary
existing workbooks, implement all Excel functions, or support external/cross-sheet
references, dynamic arrays, volatile functions or macros. Identifiers requiring
exact decimal digits should be strings, as Excel numeric cells use floating point.

Optional `header` applies a dark header row and freezes it. `column_widths` accepts
widths 4..80; `number_format` applies an Excel number format to body cells.

## Fill DOCX / PPTX templates

Use `fill_office_template`:

```json
{"template_path":"template.docx","file_path":"filled.docx","format":"docx","replacements":{"{{title}}":"季度报告","{{name}}":"研发团队"}}
```

Source and output extensions must match `format` (`docx` or `pptx`). Source must
be a regular, non-symlink project file. The source is read as a snapshot and left
unchanged; output is create-only.

Placeholder matching joins text runs within a paragraph, so a token split by
Word/PowerPoint formatting is still found. Inserted text inherits the first run's
formatting. Remaining runs, style attributes and surrounding text are retained;
changed text nodes set `xml:space="preserve"`. Matching is simultaneous, not
recursive, and every requested placeholder must exist.

DOCX scope: body, headers, footers, footnotes, endnotes. PPTX scope: slides and
speaker notes. Current parser supports standard `w:t` / `a:t` text elements.
Replacements must be single-line text; paragraph loops, rich text, images, master
editing and placeholder matching across paragraph/break boundaries are unsupported.
Unchanged ZIP parts are raw-copied. Signed and macro-bearing packages are rejected.
No embedded code or external relationships are executed or fetched.

## Bounds, output and validation

Input <=1 MB, output <=20 MB. Limits: 100 slides, 30 bullets per text slide,
2000 paragraphs, 20 sheets, 10000 cells across sheet rectangles, 1000 columns,
128 formulas per workbook, 512 bytes/formula, nesting <=32. Individual text fields
are <=32000 UTF-8 bytes and reject invalid XML characters. Template limits:
100 replacements, 5000 ZIP entries, 100 MB expanded input/edited XML total,
10 MB per selected XML part and bounded replacement expansion.

All outputs reuse project-confined file handles and atomic no-clobber hard-link
publication. Filesystems without hard-link support fail without publication.
Unknown document fields and missing placeholders fail rather than silently drop
requested operations. Source/output symlinks, Git metadata and runtime history
are not allowed template targets.

Tool results contain an absolute path, formula-calculation status, and warnings.
PPT warnings estimate dense body text, long titles and crowded chart labels.
These are **heuristics, not visual acceptance**: there is no page rasterization,
font measurement, PowerPoint rendering or proof of layout fidelity. Template
outputs always request a visual check because replacement text can change layout.

## Tests and next steps

Integration check (2026-09-06): 164 backend tests passed, one live-provider test
ignored. Core library Clippy (`-D warnings`) and GPUI check with Rust 1.96.1 passed.

Tests independently read DOCX/PPTX content through the native attachment extractor
and XLSX values/formula caches through Calamine. Chart tests open the embedded
workbook and compare series data. Template tests verify split runs, escaping,
unchanged package parts, slide/notes changes, missing placeholders and actual tool
path/permission enforcement. These checks do not replace real Office application
rendering or Windows package verification.

Keep adapters under `office/`: `charts.rs`, `spreadsheet.rs`, `template.rs`.
Next evaluate a Rust renderer against real Office screenshots, then add template
image/chart edits and existing-workbook recalculation. Do not label an approximate
HTML/PDF recreation as a faithful Office preview.
