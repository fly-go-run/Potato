# 原生 prompt 资源

这些资源由 `potato-core` 编译进应用，服务于 GPUI 的原生调用链。修改后需要重新构建客户端；不会热更新正在运行的已安装程序。

| 文件 | 用途 |
| --- | --- |
| `core.md` | 任务范围、完成标准、途中纠正、证据与表达 |
| `workspace/*.md` | 中、英、印尼、俄四种语言的可编辑工作区默认文档 |
| `memory.md` | 文件记忆的检索、global/project 写入和数据库文档边界 |
| `skills.md` | 技能选择、`read_skill` 引用读取和缺失处理 |
| `scheduling.md` | 定时任务、时区、后台作业与运行条件 |
| `summary.md` | 历史压缩交接；不会授予新的执行权限 |

`workspace.rs` 始终注入核心规则，即使用户清空了工作区文档选择。`model.rs` 附加记忆、技能、通用权限与调度规则；具体工具 schema 留在 `tool_registry.rs`。当前时间、项目和有效权限放在每轮的 runtime context，保持静态前缀和工具排序稳定。权限说明只解释当前模式，不改变执行层权限。

时间上下文提供 UTC 和主机当地时间。主机 IANA 时区从有效的 `TZ` 或 `/etc/localtime` 的 zoneinfo 路径读取；无法可靠识别时明确标记未知，仅提供当前偏移，不能凭偏移猜测时区或夏令时规则。Windows 等无法通过这些入口提供名称的系统仍可根据用户指定时区创建任务。

## 兼容已有工作区

- 工作区 `AGENTS.md` 仅在全文与旧版四语默认模板之一完全一致时升级，保留创建时间、其他文档和文档选择顺序。识别时不依赖当前 UI 语言。修改过或删除的文档不覆盖、不重建。
- 旧模板资源仍由 `workspace.rs` 引用用于精确匹配；不要在删除旧目录时遗漏这项编译依赖。
- 已保存的旧默认摘要 prompt 在 `Policy` 反序列化时采用新默认；自定义摘要文本和其他策略字段保留。原始配置数据不因读取而覆写。
- 工作区 PROFILE 文档位于数据库；文件工具写入同名磁盘文件不会更新它。长期偏好应通过支持的记忆工具保存。

## 验证范围

`workspace_tests.rs` 覆盖四语默认升级、自定义保留、重启、文档选择与字节上限；`prompts.rs` 测试夏令时和未知时区；权限测试覆盖三种审批策略与三种文件模式；`tests/runtime.rs` 通过本地模拟服务验证 Chat Completions 和 Responses 均收到新规则，动态时间与权限不混入静态 system 内容。上下文回归仍要求实际触发压缩并保留用户请求与完整工具配对。

这些测试验证组装、协议、迁移和运行边界，不衡量模型是否更少确认或更可靠地完成任务。真实模型效果需使用 [源码对照报告](../PROMPT_CODEX_REVIEW_2026-09-08.md) 中的场景做行为评测。
