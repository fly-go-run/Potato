# 排队发送与立即打断：调研及交互方案

日期：2026-09-06。阶段：原生实现与自动化测试已完成，真实桌面窗口视觉验收待执行。

## 参考产品核实

| 产品/入口 | 排队与即时输入 |
| --- | --- |
| Codex 桌面说明 | Queue 等当前 run 完成后开始下一 run；Steer 加入当前 run。输入框上方的队列可编辑、排序、发送、删除；设置可选择默认行为。文档不为所有桌面版本固定同一快捷键。 |
| Codex IDE 扩展 | 官方设置表的 followUpQueueMode 默认为 queue；Cmd/Ctrl+Shift+Enter 临时反转行为。不能把它写成所有 Codex 入口都用 Cmd+Enter。 |
| Codex CLI | 官方说明 Enter 为 steer，Tab 为 queue，与桌面/扩展默认不完全相同。 |
| Claude Code CLI | Enter 排队，在输入框上方展示；普通消息可能在当前工具调用结束后就并入同一轮，剩余消息才在整轮结束后按最早条目启动后续轮。Esc 中断后处理待发送内容。Up 可取回待发送内容编辑。 |

来源：
- https://learn.chatgpt.com/docs/prompting#steering-and-queuing
- https://learn.chatgpt.com/docs/developer-settings#editor-settings-reference
- https://code.claude.com/docs/en/interactive-mode#queue-messages-while-claude-works

结论：复用“输入框上方可见队列”和双发送意图，具体时机遵循用户对 Potato 的要求：严格等完整回复结束，不在工具间隙偷偷插入。

## Potato 当前状态

- `native/potato-gpui/src/main.rs::send` 在 streaming 时 POST `/api/agent/steer`，只支持文字，不支持本轮追加附件。
- `native/potato-core/src/steering.rs` 把补充指令持久化到 transcript，并在完整模型/工具交换边界交付；这是一种安全边界上的 steer，不是下一轮队列，也不是立即取消。
- 当前发送图标在运行时变为停止，旁边是“补充指令”，没有待发送管理区。
- `Runtime::cancel` 与模型/命令 cancellation 已存在；本轮窗口端到端验证过停止和停止后继续。新增立即发送应复用取消路径，并等待旧 run 退出，不能取消后立刻并发 start。

## 统一交互规则

| 状态/操作 | 行为 |
| --- | --- |
| 空闲，Enter 或发送 | 正常发起一轮 |
| 回复中，Enter 或“加入队列” | 持久化一条待发送消息，成功后清空当前草稿；保持当前回复 |
| 回复中，点击“立即发送”或 ⌘Enter | 把当前草稿提升为紧接着执行的消息；先请求停止当前 run，确认结束后发送 |
| 任意时刻，Shift+Enter | 换行；中文输入法组合期间 Enter 只确认候选，不触发提交 |
| 已排队条目，“立即发送” | 仅提升选中条目，其余条目保留顺序；当前草稿不变 |
| 手动点击停止 | 停止当前 run 并暂停自动队列，不要刚停止就又自动启动 |
| 正常完成 | 逐条发送 FIFO 队首，每条是一轮，不能一次合并所有内容 |
| 错误/断线/初始化失败 | 保留待发送内容并暂停；显示原因与“继续发送”，避免错误循环 |
| 重启 | 恢复队列并置为暂停；用户点击继续后执行 |

Windows/Linux 使用 Ctrl+Enter 作为立即发送。⌘Enter 是 Potato 按用户要求选择的快捷键，不冒称是两个参考产品统一默认。

立即发送是“停止并发送”，已经完成的文件写入等操作不会回滚。取消期间显示“正在停止，随后发送…”，禁止重复提升或创建第二个同会话运行。若已经自然完成，原子地转为直接发送。停止超时保留该消息、暂停队列，不强行并发启动。

## 队列区

已按用户选择确定为 Codex App 式紧凑附属队列。视觉稿：`codex-app-selected.png`；真实参考与来源：`references/README.md`。视觉稿用于结构与层级，原生实现以以下尺寸和既有输入框工具栏为准。

- 队列紧贴输入框上沿，左右各内缩 12px，上方圆角 16px；浅灰底、细边框，与输入框衔接，无独立标题和说明区。空队列完全隐藏。
- 每行高 36px，左侧 16px 队列图标，中间单行摘要，超长省略；右侧“立即发送”、删除、更多。附件以小图标与数量表达，不增高行。
- 默认展示最多三行；更多时提供“还有 N 条”展开入口，展开后最高 180px，内部滚动。条目使用正常布局，禁止叠压。
- 更多菜单含编辑、上移、下移；悬停/聚焦显示拖动手柄。编辑在原条目内展开，保留独立草稿，保存前队首不自动消费。Escape 取消编辑。
- 输入框严格使用单行底栏：左侧添加、目录、权限；右侧模型选择、语音、唯一主操作按钮，全部垂直居中，禁止换行及额外停止/发送双按钮。运行且草稿为空时主按钮显示停止；有草稿时显示发送箭头，Escape 仍可停止（中文组合态除外）。发送菜单可选“加入队列 ↩”和“打断并发送 ⌘↩”。Enter 默认排队。
- 队列条目的“立即发送”只提升该条，不发送当前输入框草稿。悬停提示“停止当前回复并发送这条消息”。
- 暂停、取消中和错误才显示一条紧凑状态行；正常等待无需额外标题。取消中显示“正在停止，随后发送…”，禁用重复提交。
- 等待审批或提问时，队列不能覆盖交互卡，也不能视为批准或回答；立即发送走显式取消路径。
- 图标按钮点击区域至少 28px，具备可访问名称、焦点环与键盘访问。中文输入法组合态不提交。

## 实现建议

在 Rust 核心增加独立 outbox，而不是复用 steering_state=queued：后者会提前注入当前轮。

消息字段建议：id、session_id、user_id、position、content/attachments、created_at、revision、state、client_message_id；模型/项目上下文保存发送时快照，执行时重新检查当前权限。附件先入应用管理的持久化存储，不能只保留 /tmp 原路径。

队列状态：pending / editing / dispatching / sent；会话另有 paused 状态。服务端按会话锁和 SQLite 事务执行 claim，`client_message_id` 做幂等防重复。提交只在确认持久化后清空输入框；新轮创建与队列消费需要原子关联，崩溃后按 request/chat 关联恢复，不能宣称端到端网络 exactly-once。

建议新增 outbox 增删改查/排序/promote/resume API。队列调度放在 core 而不是窗口 terminal 回调里，否则窗口切换、关闭和重连容易丢消息或重复消费。只有收到当前 run 的真正 terminal、持久化完整历史、释放 session 运行占用后，才 claim 下一条。工具完成、部分 message completed、steering delivered 都不是出队依据。

正常完成自动 drain；主动“停止并发送”记录单独 continuation 意图，以区别普通手动停止。旧 run 迟到事件按 request_id 隔离。持久化或提升失败时原草稿/条目保持可编辑。队列属于会话，切换会话时切换对应队列，不串上下文。

首版不把第三种“步骤间补充”放成同级发送模式，以免队列、steer、硬取消三者混淆。内部现有 steer API 可保留。

## 验收清单

1. 文本生成中连续排三条；工具调用结束不出队，整轮完成后严格 FIFO。
2. 文字流、工具运行、等待审批/提问分别触发立即发送；无重复运行、无孤立 tool result、无越权批准。
3. 完成与入队/提升同一时刻；取消超时、网络失败、窗口切换、重启，内容不丢失。
4. 编辑队首时当前轮结束；保持编辑锁，保存后才继续，后面的消息不越过队首。
5. 带附件排队、队列和草稿同时存在、删除及排序、模型切换、中文候选确认、快捷键。
6. 手动停止保持暂停；立即发送完成后按原有队列恢复顺序。

## 实现记录

- 核心入口：`POST /api/agent/outbox`，action 支持 list/add/delete/edit/save/cancel_edit/up/down/promote/pause/resume。队列保存在 SQLite settings 中，由 Rust 核心调度器检查整轮运行占用后逐条启动，与前端窗口生命周期无关。
- 模型选择在入队时保存；附件沿用已上传的内联 data URL。权限在执行时按现有核心逻辑检查。
- 入队请求 ID 保存最近 1024 条收据，防止近期请求重试重复入队。先持久化 dispatching，再创建运行；重启时不确定条目标记 uncertain 并暂停，需要人工检查历史后删除或编辑，未实现跨 transcript/SQLite 的原子事务。
- 编辑、删除和上移/下移可用；首版没有拖动排序手柄。悬停发送按钮展开双发送菜单，移入菜单保持，移出延迟 180ms 收起；点击默认排队，⌘Enter 打断并发送。唯一主按钮在运行且草稿为空时为停止。
- 立即发送等待核心取消完成；超过 15 秒保留消息并暂停。手动停止、失败、重启暂停队列。队列恢复仍需应用进程运行。
- 自动回复通过 replay 重新连接到 GPUI；短回复若在轮询间隔内完成，则重新读取历史。已有会话切换限制沿用原实现，运行中仍需等待或先停止。
- 已启动隔离包，检查单行底栏及队列布局，实测 Enter 排队、⌘Enter 打断、队列编辑及重启暂停。坐标操作失败，真实鼠标悬停尚未验收；最新修复包重启再次被自动审批阻止，最终对图验收仍未完成，详见 `design-qa.md`。
