# WorkBuddy 对标闭环 r4

- 基准：WorkBuddy 5.3.8 与当前 QwenPaw release 包实机对照
- 方法：独立审查先报差异，主线程修复并打包，再由同一独立审查者复验
- 原则：只借鉴任务工作台的信息架构与交互，不复制积分、活动、吉祥物等营销元素

## Cycle 1：2026-08-01

| 优先级 | 差异 | 当前证据 | 本轮处理 | 验收 |
|---|---|---|---|---|
| P0 | 会话只有标题，没有任务控制面 | WorkBuddy 顶栏有会话内搜索、历史与产物入口；QwenPaw 仅标题/运行点 | 增加会话内搜索和产物面板入口 | 长会话任意滚动位置可检索；入口键盘可达 |
| P0 | 消息内文件卡不等于任务级产物管理 | WorkBuddy 可从“查看所有产物”打开右栏；QwenPaw 文件分散在各轮 | 按会话聚合写入/交付文件，新增可收起产物右栏 | 多轮生成多个文件后统一列出，可打开并定位来源 |
| P0 | ProjectPicker 不等于项目/空间 | WorkBuddy 有项目一级入口及项目内任务；QwenPaw 的真实模型是本地 coding workspace | 不伪造协作项目；按真实 session-project binding 在侧栏分组，会话头与搜索结果显示工作区 | 同一工作区历史聚合展示；当前任务身份可见 |
| P0 | 模板卡不等于自动化闭环 | WorkBuddy 有“定时任务/运行记录”；QwenPaw 原先只有任务与模板 | 增加全局“运行记录”页签，聚合所有真实 job history，部分接口失败可降级 | 可追踪运行中/成功/失败、触发方式与对应任务 |
| P1 | 左上角入口需贴合用户补图 | 用户圈定“侧栏开关 + 加号气泡”；全局搜索已有 `⌘K` 与侧栏入口 | 展开/折叠态统一为 `PanelLeft + MessageCirclePlus`，搜索保留但不重复占顶栏 | 两态 tooltip、图标与行为一致 |
| P1 | 顶部拖拽缺少系统化采样验收 | 源码和单点实拖已通过，但各页面/状态未形成矩阵 | 打包后覆盖 5 个顶部采样点 | 展开/折叠及首页/会话均可拖，按钮不误触 |
| P1 | 会话缺耗时、模型与更多动作 | WorkBuddy 每轮提供状态、耗时、模型与反馈动作 | 后续循环按真实后端元数据补，禁止伪造 | 元数据真实、动作可用且可键盘聚焦 |
| P2 | 首页缺工作上下文 | QwenPaw 首页只有标题、chips、composer | 后续结合项目补最近项目/继续任务 | 首屏展示真实工作上下文，不加营销噪音 |

## 不照搬

- 活动、积分、推广卡和吉祥物。
- 没有后端能力支撑的分享、朗读、反馈、假状态开关。
- WorkBuddy 的三场景营销 tab；QwenPaw 保持“把任务做完”的单一产品签名。

## Cycle 2：Cycle 1 独立复审问题

| 优先级 | 复审发现 | 修复 | 自动验收 | 独立复验 |
|---|---|---|---|---|
| P0 | 首批 API 悬挂或一次 invoke 失败时，桌面窗口可能永久隐藏 | 前端最多等待 1.5s 后 reveal；invoke 短退避重试 3 次；原生导航后 12s 仍隐藏则兜底 show | `npm build`、`cargo check` 通过 | Cycle 2 发现 ready 协议前仍有边界，转 Cycle 3 |
| P1 | 失败、取消、无输出或执行中的写文件步骤会误入产物 | `FileToolCard` 与任务产物栏统一要求“收到 completed 输出且明确成功” | 覆盖失败/取消/执行中/无输出 | Cycle 3 发现消息流勾号仍不一致，转 Cycle 4 |
| P1 | Overview 把失败/取消都标成“已完成” | 直接读取 `stream.responseStatus`，分别映射运行、完成、失败、取消 | 参数化覆盖 6 种状态 | PASS |
| P2 | Tailwind 扫描文档中的伪类名，生产构建产生非法 CSS warning | 文档改为三个真实 shadow 类的枚举 | 最新生产构建无 CSS warning | PASS |

## Cycle 3–4：边界收敛

| 优先级 | 复审发现 | 最终处理 | 验收 |
|---|---|---|---|
| P0 | sidecar 在 ready 协议行前挂起时，导航后的 fallback 尚未创建 | sidecar spawn 后立即启动 45s generation watchdog；`frontend_ready`、12s fallback、45s watchdog 竞争同一单次 reveal claim；重启时 reset | Rust 单次互斥/跨 generation reset 测试通过 |
| P1 | 正常启动后用户主动隐藏，旧 fallback 可能重新 show/focus | 所有自动 reveal 必须先 claim；React 已 ready 或任一 fallback 已执行后，其余任务自动失效 | 独立源码复审 PASS |
| P1 | `denied/interrupted/cancelled` 不进产物，但消息卡仍显示成功勾 | 通用工具卡、文件工具卡、任务产物与完成步骤统一使用 trim/lower 状态分类：空旧历史、success、completed 为成功；created/in_progress 为运行；其余为失败 | 前端 19 文件、93 测试通过；Cycle 4 独立复验 PASS |
