## A. 设置窗口

### A1【P0·观感】打开设置后,背后是一片空白
`/settings` 是独立路由,ChatView 被卸载,模态背后只剩空画布。观感像"应用坏了"。ChatGPT/Codex 的设置都是悬浮在当前页面之上。
→ **改成真正的覆盖层**:设置模态不再换路由(改全局状态触发),或用背景路由技术保持来源页面挂载。

### A2【P0·信息架构】五分区撑不起内容量
实测内容:模型 4 行、服务商 2 组、外观 2 行、能力 1 行(还只是个跳转按钮)、安全 1 行。5 个导航项对应 ~10 行设置,短分区大片空腔,导航本身成了噪音。
→ **合并为 2~3 区**:「模型与服务商」(合并现模型+服务商)、「通用」(外观+语言+沙箱+能力入口)。导航瘦身,每区内容密度恢复正常。

### A3【P1·重复】设置「模型」分区与 composer 的 ModelPicker 完全重复
同样的 供应商→模型 二级选择,两个入口改同一个 agent 配置;用户不知道该在哪改、两处有什么区别。
→ 设置侧**去掉选择职责,只留管理职责**:发现模型、增删模型、上下文窗口信息;"当前模型"改只读展示 + "在输入框处切换"提示。切换动作全部归 composer。

### A4【P1·反模式】「管理模型」是模态套模态
设置模态之上再弹一个小 Dialog,列表挤在 ~200px 高的滚动区里,添加表单贴底。
→ 并入 A2 合并后的「模型与服务商」区:选中供应商后 **inline 展示其模型列表**(删除/添加/当前标记),不再二级弹窗。

### A5【P0·心智混乱】"添加或编辑供应商"一表两用
同一个表单,靠下拉里选"已配置/未配置"项决定是添加还是编辑;列表行的「编辑」按钮的实际效果只是"把下拉选到该项",视觉反馈几乎为零。
→ **实体化**:供应商列表(含状态徽标)+ 点击进入该供应商的详情面板(key、Base URL、模型管理、删除/清除凭据都在一处);「添加」是列表底部的独立动作。一个实体一个界面。

### A6【P0·功能缺口】无法添加自定义供应商
后端有完整能力(`POST /api/models/custom-providers`,删除端点前端都接了),但新前端**没有任何创建入口**——自建 OpenAI 兼容服务(如用户自己的 sub2api 类网关)只能靠预置列表,预置里没有就接不进来。
→ 供应商列表底部加「添加自定义供应商」:名称 + Base URL + API Key 三个字段。

### A7【P0·交互硬伤】API key 失焦即保存,且无法清空、无法验证
- blur 自动保存:误粘贴即写入,无确认、无撤回;
- "留空则保留现有 key" ⇒ **不存在清空 key 的途径**;
- 保存后没有任何连通性反馈,key 错了要到聊天时才发现。
→ 显式「保存」动作;加「清除凭据」;保存后自动探活(拉一次模型列表)并显示 成功/失败 徽标——这也顺带给了"测试连接"能力。

### A8【P2·细节】服务商分区内容贴模态底边
最后一行(Base URL)几乎贴着模态下边缘,有"被裁切"的错觉。内容区 `pt-0` + 底部留白不足。
→ 分区底部统一 padding;配合 A2 合并后自然缓解。

### A9【P2】「能力」区的按钮把用户甩出设置
点「管理」→ 关闭设置模态跳 /skills 全页,上下文断裂,回来要重新打开设置。
→ 并入「通用」区后保留跳转但预期明确;或就地展示技能开关摘要(后续包)。
