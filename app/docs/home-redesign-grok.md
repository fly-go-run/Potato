# 首页空态重设计意见

读过 `ChatView.tsx` 空态（约 648–665 行）与 `CapabilityChips`（61–240），并核对 `Composer.tsx`、`stores/chat.ts` 的 `sendMessage`、`i18n.ts`。只谈取舍，不改产品代码。

## A. Slogan

现文案「Potato，帮你把工作做完」有三处不适：承诺过大（工作很少「做完」）、品类套话、侧栏已有品牌却再喊一遍。

候选：

1. **下午好，从哪件事开始？** — 问候 + 任务问句。推荐。
2. **有事直接说** — 桌面 agent 口吻，短，不承诺结果。
3. **今天做哪件？** — 比「做完」具体，和输入框衔接。
4. **Potato，开工** — 留品牌、去鸡汤。
5. **今天帮你做哪件？** — 保留服务视角，去掉绝对化。

**不要只用「早上好 / 下午好 / 晚上好」。** 问候有温度，单独放则空：深夜别扭，也没说这是干活的产品。推荐「时段问候 + 轻问句」，标题去掉 Potato。注意：现占位已是「今天帮你做点什么？」——标题若再问一句会叠。标题用问候，占位改成动作提示（见 C）。

## B. 三个场景 tab：同意删

`category` 是组件内 `useState<"office"|"code"|"design">`，默认 office。点 tab 只换 chips 分组并清空选中；点 chip 只 `setComposerDraft(t(prompt))`，填输入框，不发送。全仓库只有这里写 draft。`sendMessage` 的 `request_context` 只带 `approval_level` 和可选项目路径，**不读 category，不改 system prompt，不换工具集**。三套 `chat.suggest.*` 也只服务这排 chips。

删 tab 零后端风险。若 chips 一并删，整段 `CapabilityChips` 和 `chat.category.*` / `chat.suggest.*` 可清；顺带收掉标题下 `mt-12` + chips 上 `mt-14` 的空档。

## C. 建议 chips

**选 c1，现在就删。** 用户不用；侧栏已有最近会话；composer 已有 `/` 技能、`@` 文件。静态「写周报 / 做 PPT」是过期的能力说明书，还跟标题抢第一视觉。

- **c2 否。** 「继续上次」等于侧栏第一项。空态没有会话文件，最近文件常为空，做出来是空壳。
- **c3 否。** 17 个技能铺首页，清晰感重构白做；技能已有 `/` 和「技能与插件」页。
- **c4：** 删 chips 后，把发现性欠账补在问候下的一行 12px tertiary：「输入 / 调用技能，@ 引用文件」——只给前几次空态，或第一次触发 `/` `@` 后不再出现。不要再做第二排入口。

## D. Composer 缩写（已拍板，只评风险）

「自动」有轻歧义（自动模型 / 自动发送 / 自动审批）。盾标偏「安全」不偏「自动」。可接受，前提是：**下拉项保留全称 + 已有 hint**；「关闭」在菜单里不要缩成孤词，用「不询问」或「审批关闭」。触发器补 `aria-label="审批：自动"`（代码已强调档位是安全边界）。

「默认」风险低：文件夹图标够，且只在未绑项目时出现；有项目时已显示项目名。`title` 已是全称，保持即可。
