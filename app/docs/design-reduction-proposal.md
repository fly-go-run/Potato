# 减法重构提案：右侧栏 / 顶栏按钮 / 设置界面

判据只有一条：**每个元素必须回答用户的一个真实问题**。回答不了的删，
重复回答的合并。以下按面拆解，每节末尾给结论分级
（删 / 合 / 改 / 保）。

## 1. 会话右侧栏（ConversationSidePanel）

### 1.1 总览 tab —— 建议整个删掉

逐项过堂：

| 元素 | 它回答了什么问题 | 判决 |
|---|---|---|
| 运行状态点 + 「正在执行」 | 任务在跑吗 | 会话流本身已经在答（spinner、流式文本）。重复。 |
| 消息 N | 无。用户从不需要知道会话有多少条消息 | 调试遥测，删 |
| 完成步骤 N | 无。「步骤」是内部工具调用计数，用户没有这个概念 | 调试遥测，删 |
| 模型 gpt-5.6-terra | 当前用的什么模型 | composer 的模型 chip 已经答了，而且这里打的是 raw id，连产品名都没走（`prettyModelName` 未接）。重复 + 低质量。删 |
| 「文件改动：还没有文件改动」卡 | 有没有改动 | 改动 tab 自己会答。转述别的 tab 是导航失败的补丁。删 |
| 「产物：还没有产物」卡 | 有没有产物 | 同上。删 |

总览 tab 是一块"仪表盘化"的惯性设计——把系统状态铺给用户看，
恰好就是用户批评的"尽可能多给信息"。它没有一行内容是独有的。

### 1.2 结构：三 tab → 单面板两段

删掉总览后只剩改动/产物两个列表，两个 tab 装两个列表是过度结构。
方案：**一个滚动面板，两个分区**——"改动"在上（带 ±行数的文件行，
现有样式保留），"产物"在下。哪个分区空就整段不渲染；两个都空时
显示一个居中的静音空态（一行字，不要两行解释文）。

连带删除：
- tab 上的计数 `改动 3 / 产物 2`——和侧栏「会话（46）」同病，
  列表自己就是计数。
- 产物卡里的「定位到会话 ›」次级按钮行——保留能力但降级为
  hover 才出现，常态不占一行。
- 空态第二行解释文案（noArtifactsHint / noChangesHint）——
  "会集中出现在这里"是对着空房间介绍房间。

保留派最强反驳：总览的"运行状态"在长会话里有集中查看价值。
回应：状态与其在第三个 tab 里，不如做成面板顶部一行（跑着时才出现
一个 spinner 行），不需要一个 tab 的位格。

### 1.3 面板打开按钮的数字角标

`9+` 角标是通知语义（未读、待处理），但改动数不是待办，
看不看都不欠着用户。删角标；面板有内容时给图标一个 tint 色点
（或什么都不给）就够了。

## 2. 会话页右上按钮（搜索 / 面板开关）

- 激活态 `bg-fill-active` 是常驻灰块——和收起态浮条灰底同一个病：
  **状态该由内容面板自己表达**（搜索浮层开着、右栏开着，用户看得见），
  按钮不需要再举个灰牌子。改成与侧栏同一套 alpha 阶梯，激活态用
  图标变 `--icon-strong` + 8% 底，关掉浮层即回落。
- 搜索浮层里的提示句「输入关键词检索用户与助手消息，按回车跳到下一条。」
  ——placeholder 已经写了"搜索当前会话内容"，这句是第二遍说明书。
  空态直接留白。回车跳下一条属于用了就会发现的行为，不值一行常驻文案。
- 图标：`PanelRightOpen` 的箭头是"动作暗示"，实际这是开关。
  换 `PanelRight`（纯形状，无箭头），与侧栏 `PanelLeft` 成对。

## 3. 设置界面

### 3.1 当前模型卡

「5.6 Terra / sub2api · 上下文窗口 1,050,000 tokens」：

- 上下文窗口是参数表数据，不回答用户在设置页的任何问题
  （要选模型时，长短在模型菜单里比较才有意义）。从卡上删，
  留在供应商详情的模型行里。
- sub2api（供应商）保留——回答"这个模型从哪来"，点进哪个供应商
  改配置需要它。
- 卡不可点是死端。改成整卡可点 → 跳到该供应商详情。

### 3.2 服务商列表 —— 一墙 12+ 行是主要病灶

逐项：
- `sk-******` 掩码：六个星号对所有 key 都一样，唯一信息量是
  "配了 key"——但绿色「已配置」badge 已经说了。**双重状态，删副行**。
- 「本地服务，可直接使用」×3：一句话说三遍。「本地」badge 已经在了，
  副行删。
- 「已配置」badge 与「未配置」副行文字：状态只允许一个表达位。
  规则：**配了的不用说配了（有模型数就是证明），没配的说一次**。
- 结构级方案：列表按状态分两段——
  **已配置（含本地）平铺在上**，行 = 名字 + N 个模型 + chevron；
  **未配置的 8+ 行折叠进底部「添加服务商 ›」一行**，点开才展开
  （与现有「添加自定义供应商」合并成同一个入口）。
  设置页首屏从 12+ 行降到 5-6 行，全是与用户有关的。

保留派最强反驳：平铺让用户"发现"可以接 OpenRouter/GitHub Models。
回应：发现是首次配置期的需求，之后每次打开设置都付出一墙未配置的
代价。折叠行上写「添加服务商」已足够承担发现职责。

### 3.3 master-detail 结构

保留。连接/测试/模型管理放详情页是对的，病在列表密度不在结构。
